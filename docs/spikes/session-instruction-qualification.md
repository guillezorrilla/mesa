Mesa's tmux backend had matched every `error connecting to` string as "no server", so a nested `mesa sessions --json` or `mesa show --json` falsely appended `exited` events to live records. The headless run similarly ended before Codex's turn completed. The backend now recognizes only `error connecting to ... (No such file or directory)` as an absent server; a sandbox denial is an error. In a fresh native session `cwpcz65m`, `mesa show --json` returned that error, the session answered normally, and its record stayed alive with no `exited` event. A new native headless run then completed. This preserves native permission prompts and prevents false lifecycle writes, but nested live coordination in the default Codex sandbox must either receive native approval or report that live tmux is unavailable.
