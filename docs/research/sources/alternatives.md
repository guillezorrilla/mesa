# Session Board: existing tools survey

Access date for every source below: **2026-09-24**. Sources are GitHub repo metadata (via `gh api`), each project's own README, and official docs/marketing pages. No feature is listed unless it is stated in the README or official docs; anything inferred is marked "unclear from README."

Scope: tools that could plausibly cover Mesa's Session Board - one screen listing every running Claude Code / Codex CLI session across many repos, with state, last output, running time, attention ranking, and the five actions (start, stop, send, open terminal, resume).

## Recommendation

**No single tool covers the full Session Board for both Claude Code and Codex.** The closest whole-product candidates each fail a different hard requirement:

- **CCManager** has the best state model (fine-grained idle/busy/waiting_input, per-agent detectors, documented restart-persistence) and covers Claude Code + Codex, but has no `--json`/API surface at all (only fire-and-forget shell hooks) and does not attach to sessions started outside itself - it owns the whole lifecycle via its own PTYs, not a "reachable from a plain terminal" tmux session.
- **Happy Coder**'s `happy-agent` CLI is the closest match to `mesa --json` (every subcommand - list, machines, spawn, status, send, create - takes `--json`) and explicitly supports both Claude Code and Codex, but its backend is a relay daemon + E2E-encrypted sync service, not tmux, so "open its terminal" and "reachable from a plain terminal" don't map cleanly onto it.
- **NTM** is architecturally closest to what Mesa is building (tmux backend, REST/WebSocket/OpenAPI, `--robot-snapshot` JSON, checkpoints for persistence, dashboard) and supports both agents, but it's a heavyweight orchestration layer (work triage, Agent Mail, safety policy, approvals) bolted onto session management, it's very young (three months old), and its license badge reads "MIT+OpenAI/Anthropic Rider" - a non-standard term worth legal review before borrowing code.

**Three sources worth borrowing specific techniques from**, each covering a piece Mesa still needs to build:

1. **CCManager - state detection.** Per-agent output-pattern detectors with an idle-debounce to avoid false transitions during terminal redraws:
   `https://github.com/kbwo/ccmanager/blob/main/src/services/stateDetector/claude.ts` (spinner-regex + prompt-box border detection + `IDLE_DEBOUNCE_MS`) and the sibling `codex.ts` in the same directory for the Codex equivalent. The status-hook env-var contract is at `https://github.com/kbwo/ccmanager/blob/main/docs/status-hooks.md`.
2. **recon - attaching to sessions started elsewhere.** Reads `tmux list-panes` for PID/session name, cross-references Claude Code's own `~/.claude/sessions/{PID}.json` and `~/.claude/projects/…/*.jsonl`, and layers `tmux capture-pane` on the status bar for the visible state. This is the exact recipe for a tmux-backed board that stays reachable from a plain terminal: `https://github.com/gavraz/recon` (README "How it works" section has the architecture diagram).
3. **Happy Coder (`happy-agent`) - the JSON CLI shape.** Command surface (`list --json`, `machines --json`, `spawn --json`, `status --json`, `send --json`, ID-prefix matching, `--wait`) is a ready template for `mesa`'s own `--json` flag: `https://github.com/slopus/happy/tree/main/packages/happy-agent` (README).

Worth a secondary look: AgentAPI's terminal-snapshot-diffing technique for turning raw PTY output into discrete "messages" (`https://github.com/coder/agentapi` README, "Splitting terminal output into messages") - useful for the "last output" field even though the project itself is deprecated.

## Open questions

- Does Mesa need an attention-ranking algorithm from scratch, or can CCManager's state-transition timestamps (idle/busy/waiting_input + duration) approximate one? No surveyed tool implements ranking beyond "highlight rows waiting for input" (recon) - this looks like a genuine gap, not something to borrow.
- Is Claude Code's own `~/.claude/sessions/*.json` / `~/.claude/projects/*.jsonl` file format stable enough to depend on (recon depends on it; not documented as a public API by Anthropic)?
- NTM's non-standard license rider needs a legal read before any code or technique is copied verbatim rather than reimplemented from the README description.
- Whether Codex CLI exposes anything equivalent to Claude Code's hook events for permission/notification state (the observability tool and the hooks doc referenced above are Claude-Code-only); this determines whether Mesa's Codex state detector must be pure output-parsing like CCManager's `codex.ts`.
